linking
  optional "require link confirmation" to finalize activation
  same current password on both required
  enter url or browse on client
  client encrypts random with secret n + x rounds, sends n + x + y rounds 
    secret too, sends own ip and external url (if has) and random secret and random id (y from n + x)
  server has secret n + x rounds, decrypts, verifies sent n + x + y rounds 
    secret, returns own ip and external url (if has) and whether or not confirm required, stores random secret and id 
sending
  try external url with verify if has, discovery if not or if fails (all ssl ok)
    remember for awhile (have expiration)

    rounds (y from secret) and url and test value
  return same (other ip) (incremented test value), ssl signature
